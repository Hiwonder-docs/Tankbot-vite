6.6.1 WonderLLM Module Introduction ​

6.6.1.1 Module Introduction ​

The WonderLLM Module is a large AI model module with a built-in high-performance ESP32-S3 chip. It integrates a 2-megapixel HD camera, a microphone, an HD display, a speaker, and a CI1302 Voice Recognition Chip, deeply fusing multiple models including text, voice, and vision.

This module is easy to operate and is commonly paired with robots. It acts like a "super brain" for the robot, enabling a deep understanding of spoken commands and endowing the robot with exceptional capabilities in perception, reasoning, and action to create a flexible and natural human-robot interaction experience!

6.6.1.2 Operating Mode Introduction ​

The WonderLLM Module supports two operating modes: offline mode and online mode. These two modes offer different features and require flashing the corresponding firmware. This chapter uses the offline mode.

  • Offline Mode

In offline mode, the module captures images through the built-in camera module and processes image data using the ESP32-S3 microcontroller. It achieves features such as video streaming, color recognition, and face recognition, and transmits data via multiple communication protocols.

  • Online Mode

Online mode supports large AI model voice interaction and uses a command-word wake-up mechanism. Speaking the wake word is required to wake up the WonderLLM Module, and human-robot interaction becomes available after activation. The default recognition language is English, and the English wake word is "Hello Hiwonder".

After the module recognizes the wake word, the Buzzer sounds a beep, and interaction can begin. The module supports communication in English, and it automatically identifies and switches languages based on the spoken input. If no voice is recognized within 1 min, the module enters sleep mode and requires waking up again for subsequent use.

6.6.1.4 Notes ​

  1. Ensure the module's input power supply is at least 5 V 2 A. Otherwise, the image may show water ripples.

  2. The module comes with default AI large model features from the factory. Changing the features requires flashing the corresponding program.

c
			case 1:
					x_bias = Color.ColorResults[RED - 1][0] - CENTER_X;
					y_bias = Color.ColorResults[RED - 1][1] - CENTER_Y;
				
					x_bias_abs = abs(x_bias);
					y_bias_abs = abs(x_bias);
  1. After obtaining the target offset, process the X-axis coordinate offset according to specific mapping and weighting rules, accumulate it into the initial servo position offset x_inc_total, and apply limit constraints to x_inc_total. Call the robot_arm_knot_run function so that Servo 6, which controls the movement of the end coordinate point of the robotic arm along the X-axis, moves by x_inc_total based on its initial position value, achieving tracking movement of the robotic arm along the X-axis. The processing along the Y-axis follows the same principle and is not repeated here. Finally, reset the branch to re-acquire live data from the vision module in the next round for subsequent tracking.
c
					if(x_bias_abs > 8)
					{
						x_inc_total += 1 * map((float)x_bias, -120.0f, 120.0f, -2, 2);
						x_inc_total = x_inc_total < -375 ? -375 : x_inc_total > 375 ? 375: x_inc_total;
						robot_arm_knot_run(6, (int)(SERIAL_SERVO6_RESET_DUTY - x_inc_total), 10);
					}
					
					if(y_bias_abs > 8)
					{
						y_inc_total += 1 * map((float)y_bias, -120.0f, 120.0f, -1.5, 1.5);
						y_inc_total = y_inc_total < -480 ? -480 : y_inc_total > 50 ? 50: y_inc_total;
						robot_arm_knot_run(3, (int)(SERIAL_SERVO3_RESET_DUTY - (int)y_inc_total), 10);
					}
			
				fsm_state = 0;
				break;

  1. In the loop() function, the program uses a finite state machine to control the visual line following process. The state machine contains two states: case 0 handles target detection, and case 1 handles motion control. In the case 0 state, call the cam.color_position(RED) function to obtain the position information of the red line. This function reads the X and Y coordinates, width, and height of the red target from the vision module, and stores them in the cam.ColorResults[RED - 1] array. When a red target is successfully detected, the state machine switches to the case 1 state to execute motion control.
cpp
void loop() {
  switch(fsm_state)
  {
    case 0:
      // Obtain the red position
      if(cam.color_position(RED))
      {
        fsm_state = 1;
      }
      break;
  1. In the case 1 state, first calculate the area of the detected red region by multiplying the width by the height, and determine whether it is greater than 20 pixels to filter out interference. If the condition is met, obtain the X-coordinate of the red line from cam.ColorResults[RED - 1][0] and subtract the screen center coordinate CENTER_X, which is 80, to calculate the offset x_bias of the line from the center. Take the absolute value and determine whether the offset is greater than 1 pixel. An offset of less than 1 pixel indicates that the line is essentially at the center position, requiring no steering correction.

  1. When the absolute value of the offset is greater than 1, call the map function to perform value mapping. The map function linearly maps the X-axis offset from the range [-80, 80], which represents the possible position range of the line, to the range [-0.35, 0.35], which represents the steering speed of the chassis. A larger offset results in a higher steering speed. The mapped value x_inc_total is the steering speed required by the chassis. To avoid frequent minor steering adjustments, a deadband evaluation is set: if the absolute value of x_inc_total is less than 0.05, the offset is very small, and the chassis moves straight forward at a speed of 50. Otherwise, the chassis moves forward at a speed of 50 while executing steering correction. Note that the steering speed takes a negative value to achieve reverse deviation correction. After completing one control cycle, the state machine resets to 0 and enters the next round of target detection, forming a closed loop of detection, control, and detection.

  1. The custom map function implements value mapping by linearly mapping the input value x from the range [in_min, in_max] to the range [out_min, out_max]. This function converts the visual offset into the chassis steering speed.
cpp
static float map(float x, float in_min, float in_max, float out_min, float out_max)
{
    return out_min + (x - in_min) * ((out_max - out_min) / (in_max - in_min));
}
